# Dung、Kang、Luo 适配实现的坍缩修正

## 问题定位

三种适配实现出现“只剩少数节点但曲线严重偏离”并不是同一个原因：

- Dung：串行分段分别满足局部最大误差，但当前适配只把段边界转换成单重节点；最终全局三次 B 样条具有更强的连续性约束，因此局部分段可行不代表公共 refit 可行。
- Kang：旧适配对所有活跃簇无条件运行 Algorithm 4，会把海岸线上的整段长活跃簇压缩成 1–2 个节点。论文只建议在活跃节点形成明显小簇时使用 Algorithm 4；一般数据应使用 Algorithm 1，论文也存在跳过第二阶段的数值例子。
- Luo：局部极大值筛选会排除首尾跳跃；当跳跃序列平滑、单调或只有一个显著峰时，固定 `eta` 可能只保留一个候选，DE 只能移动这些节点，不能补回已删除的组合。

## 修正方式

正式横向比较默认启用一个明确标注的公共 MSE 可行性保护层：

1. Kang 先修正算法分支：只有簇长度不超过 `degree+1` 的明显短簇才运行 Algorithm 4；长簇保持稀疏阶段节点，不再错误合并。由于当前适配没有复现 Algorithm 1 的重复凸优化，这一点会明确写入诊断。
2. 先完整运行论文适配的原生阶段；原生结果达到公共 MSE 阈值时不做任何修改。
3. 原生结果未达标时，从论文阶段产生的候选和同容量均匀网格中，在当前最大残差附近补充一个节点。
4. 每轮只比较距离最大残差最近的三个位置，并执行精确的 CPU float64、端点约束标准 B 样条 refit。
5. 达到阈值立即停止；若残差引导路径在容量内仍失败，再与完整均匀容量 refit 比较并保留 MSE 较低者。
6. 最大内部节点数不超过各方法声明的统一容量，保护层耗时计入该方法完整时间。

保护层不读取网络、真值参数或真值节点，也不冒充论文原始步骤。JSON 中同时保存原生 `K/MSE`、是否触发保护层、新增节点、额外 refit 次数和最终来源；`summary.csv` 另外汇总保护层触发率、保护前通过率和保护前平均 K。因此可以同时报告“论文适配原生行为”和“统一阈值协议下的最终结果”。

## 使用方式

正式 benchmark 和真实案例绘图默认启用保护层。若要复现并诊断原生坍缩，增加：

```bash
--no-published-feasibility-safeguard
```

正式结果的方法名必须写为 `threshold-safe adaptation` 或“适配实现 + 公共 MSE 保护层”，不能把保护层后的结果称为论文作者原始算法结果。

## 回归验证

仓库测试包含一条海岸线型多频曲线。Dung 和 Luo 的原生适配超过 `MSE=1e-4`，保护层在 28 个内部节点容量内恢复可行性；Kang 则验证长簇不会再进入 Algorithm 4，保留 28 个稀疏阶段节点并达到阈值。所有结果都保留原生阶段诊断。
