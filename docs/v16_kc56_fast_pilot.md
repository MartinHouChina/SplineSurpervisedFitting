# v16 Kc=56 快速诊断试验

这个试验用于先判断候选、筛选、重定位与参数头能否协同工作，不用于论文最终指标。原有 `run_v16_mse1e-4_3090.sh` 默认正式规模配置不变；只有显式传入 `--pilot-kc56` 才启用下面的短流程。

| 项目 | 快速试验 |
| --- | --- |
| 合成训练源内部节点 | K=4..44；最大控制顶点 48 |
| 候选内部节点 | Kc=56（比训练最大 K 多 12 个候选） |
| 阶段 | Proposal 48 epoch + Joint 24 epoch，其中前 6 epoch 为 selector/decoder warmup |
| 样本 | 合成训练 1500、合成验证 300、每种真实来源验证 30；真实数据不参与训练 |
| 批量 | 优化器 Batch=64；离线教师数值求解 Batch=8 |
| 误差阈值 | mean squared Euclidean MSE ≤ 1e-4 |
| 通过率参照 | 90%，仅用于实测报告/检查点排序，不是训练阶段阻断门槛 |
| 教师 | 固定 Proposal 上的 `synthetic_anchor_first`，必要时回退贪心；仍是离线缓存，不是每步 Joint 搜索 |
| Joint 更新 | Proposal/参数头学习率为 0；更新 Selector、存活节点解码器，count 损失也参与候选结构分数监督 |

首次运行（同步最新代码到 Linux 3090 后，使用全新的 run name）：

```bash
bash scripts/run_v16_mse1e-4_3090.sh \
  --pilot-kc56 \
  --prepare-real-data \
  --device cuda \
  --run-name candidate_selection_v16_mse1e-4_pilot_sourcek44_kc56_linux_r1
```

运行前可将 `--dry-run` 加在同一命令中，查看训练、检查点检查、六方法快速对照、四指标 PNG 和真实案例 PNG 的完整命令。中断后保持训练参数及 run name 不变，再加 `--resume-run`；已有日志不会被截断，同名新鲜训练会拒绝覆盖。不要默认用过去混合真实数据训练的 checkpoint 初始化本试验。

试验的合成对照**另行**生成 K=4..56 测试曲线，K=45..56 属于训练范围外的压力测试。基准脚本通过 `--synthetic-test-max-control-points 60` 仅扩展测试生成器，不改训练数据；训练最大控制顶点 48、测试最大控制顶点 60 和逐条样本选择都记录于 `experiment.json`。六方法的共同数值初始上限为 56，网络的上限也为 56。快速档每个 K 仅抽 1 条、每类真实数据仅抽 5 条，因此其通过率和平均节点数波动很大，所有表图都标为 `DIAGNOSTIC NOT FINAL`。

优先检查 Proposal 在训练 K≤44 的多尺度召回和全候选拟合；再分开检查教师可行率与缓存构建耗时、一次性部署 MSE/通过率/平均 K、`ours_verified` 的额外修复及时间。若匹配失败频繁回退完整贪心，构建耗时仍可能很长；短流程**不保证**达到固定时长或阈值。当前缓存没有单独保存准确的逐样本回退率，不要从兼容字段推断它。只有快速试验证明节点数、误差与其他方法都改善后，再扩大训练覆盖到 K=56 并运行完整规模对照。

决策时先看未经数值修复的 `ours`：训练范围内 Proposal 全候选、离线教师及自由一次性掩码的达标率应逐级对照；如果教师可行而自由掩码仍大幅失效，就不能再以加节点的 `ours_verified` 通过率说明网络成功。简单曲线 K=4..20 与复杂曲线 K=21..44 应分别比较 K/MSE，而不是只看全体平均值。K=45..56 只评价越界泛化，不能反过来用来选训练检查点。教师缓存中旧 `teacher_greedy_count`/删除序列是锚定路径的兼容占位，不是实际贪心轨迹。
