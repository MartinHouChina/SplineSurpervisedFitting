# 候选生成与交互消冗框架（v7 历史设计）

> 本文记录 v7 的逐节点硬验证方案，不是当前 v8 默认部署。v8 请参阅
> [模型数据流](architecture.md)、[训练流程](training_pipeline.md) 与
> [部署流程](deployment_pipeline.md)。

## 1. 为什么拆成两部分

直接同时回归“最终数量 + 对应长度节点向量”存在离散耦合：删除一个节点后，其他节点的位置
和控制点都会改变。v7 将任务拆为：

```text
CandidateKnotHead：允许冗余，优先覆盖所有必要位置
InteractivePruningHead：读取候选间关系和拟合贡献，建议删除并精修位置
Hard verifier：用真实标准 B 样条 RMS 决定是否接受删除
```

这不是两个完全独立的网络。消冗头读取候选头的 token、候选位置，以及由这些位置实际求解
得到的系数能量、删除增量和局部残差；其位置精修又会改变部署候选集合。

## 2. 节点贡献为什么用截断幂基

三次截断幂形式为：

\[
C(t)=a_0+a_1t+a_2t^2+a_3t^3+
\sum_j b_j(t-u_j)_+^3.
\]

每个内部节点对应一列和一组独立系数，因此容易构造：

- `||b_j||²`：系数能量；
- 删除该列后的正则二次目标增量；
- 节点附近的局部残差；
- 左右间距。

这些量适合作为神经网络输入，比仅从几何 token 猜“该不该留”更可解释。但截断幂基在高阶
或节点密集时条件数较差，所以它只承担训练代理和贡献特征；最终求解仍使用数值更稳定的标准
B 样条基。

## 3. remove/STOP 与 keep 的职责

`keep_probability [B,Kc]` 是 canonical 节点存在性的辅助诊断。主结构动作是：

```text
remove_stop_logits [B,Kc+1]
```

前 `Kc` 类表示下一步建议删除哪个节点，最后一类表示 STOP。多个删除动作都安全时使用多正例
目标，不人为指定唯一顺序。

部署不会一次性按 keep 阈值删除。remove/STOP 可以提供排序和解释，但每个动作都必须通过真实
RMS 复核。

## 4. 当前训练监督

当前实现使用同一阈值下的 canonical 节点作为高召回和保留目标，并用模型候选的标准 B 样条
单节点删除 RMS 监督安全删除/STOP。解析截断幂删除增量仅作为输入和低权重辅助，不代替几何
RMS。

训练分为候选预训练和联合微调。拟合设计矩阵始终打开全部候选，避免拟合梯度推动所有 keep
概率变成 1。

## 5. Boehm 数据增强的边界

Boehm 插入可生成与原曲线完全相同的冗余样条表示，适合训练消冗头和验证节点删除实现。但
随机插入位置不由点云唯一决定，因此不能作为 CandidateKnotHead 的真实位置标签。

后续可加入离线轨迹数据：

```text
canonical 样条
  → 精确 Boehm 插入到 Kc
  → 对每个中间状态计算所有单节点删除后的标准 B 样条 RMS
  → safe_delete_mask + STOP + deletion log-ratio
```

推荐训练混合：理想 Boehm 状态、轻微位置扰动状态和 CandidateKnotHead 实际输出。无论是否
加入该增强，部署外部输入仍只有有序点云。

## 6. 能保证什么

- 每个已接受删除都满足指定 RMS 阈值；
- 最终开放曲线严格通过输入首尾点；
- 最终数量不依赖 CountHead 或分类 argmax；
- 贪心路径结束时没有可接受的单节点删除。

当前不保证所有节点子集中的全局最少。论文实验若需要更强 oracle，可在小 K 上完全枚举，或
使用有限宽度 beam search 比较贪心结果与更优组合。
